## P1. Individual: UML and Database Changes

- **Source heading:** "11/13/2026: 11:59PM (NO LATE PENALTY ALLOWED) INDIVIDUAL-150pts"
- **Deadline:** 11/13/2026, 11:59 PM. Conflicts with opening deadline 11/13/2027 ([DA-1](#ambiguity-register)).
- **Points:** 150
- **Type:** Individual (Section A)
- **Scope:** Model the overall system and the employee empID lookup in UML, apply the required key relationships and 3NF table additions to the employeeData database, then generate a schema diagram image from a DBMS tool.

### P1.1 Overall Use Case Diagram

- [ ] P1.1 One UML use case diagram depicting the overall components and their connections, including internal and external components and actors.

References: [User Roles and Permissions](PROJECT_CONTEXT.md#user-roles-and-permissions), [Required Functionality](PROJECT_CONTEXT.md#required-functionality).

### P1.2 Employee Lookup Sequence Diagram

- [ ] P1.2 One UML sequence diagram showing a general employee entering their `empID` to search the database and being shown their personal data. If not found, an error message is shown to the general employee.

References: [FR-8, FR-3, FR-1.2](PROJECT_CONTEXT.md#required-functionality).

### P1.3 Primary/Foreign Key Connections

- [ ] P1.3.1 `employees.empID` (primary) to `employee_division.empID` (foreign)
- [ ] P1.3.2 `employees.empID` (primary) to `payroll.empID` (foreign)
- [ ] P1.3.3 `employees.empID` (primary) to `address.empID` (foreign) ([CA-1](PROJECT_CONTEXT.md#context-ambiguities))
- [ ] P1.3.4 `employees.empID` (primary) to `employee_job_titles.empID` (foreign)
- [ ] P1.3.5 `employee_division.divID` (foreign) to `division.divID` (primary)
- [ ] P1.3.6 `employee_job_titles.job_titleID` (foreign) to `job_titles.job_titleID` (primary)

References: [Key Relationships, DB-2.1 to DB-2.6](PROJECT_CONTEXT.md#key-relationships).

### P1.4 Third Normal Form Tables and Demographic Fields

- [ ] P1.4.1 `addresses` table (`addressID`, `street`, `cityID`, `stateID`, `zip`) for all employees.
- [ ] P1.4.2 Additional demographic items: DOB, mobile/phone, emergency contact name, emergency contact mobile/phone ([CA-4](PROJECT_CONTEXT.md#context-ambiguities)).
- [ ] P1.4.3 `cities` table with `cityID` and city name (`varchar(25)`).
- [ ] P1.4.4 `states` table with `StateID` and 2-letter abbreviation, populated with all 50 states.
- [ ] P1.4.5 `addresses.addressID` (primary key) to `employees.addressID` (foreign) ([CA-1](PROJECT_CONTEXT.md#context-ambiguities)).

References: [Third Normal Form Additions](PROJECT_CONTEXT.md#third-normal-form-additions), [Demographic Fields](PROJECT_CONTEXT.md#demographic-fields), [Indexes](PROJECT_CONTEXT.md#indexes) (index help resource: https://www.w3schools.com/mysql/mysql_create_index.asp).

### P1.5 Generated Schema Diagram

- [ ] P1.5 After the P1.3 and P1.4 additions/changes, create a database schema diagram generated from a DBMS tool (dBeaver or SQL Workbench), and generate an image of the diagram.

**Formats, tools, and rules**

- Schema diagram must be generated by dBeaver or SQL Workbench and submitted as an image.
- UML diagram rules from [Shared Submission Rules](#shared-submission-rules) apply to P1.1 and P1.2.
- Must use MySQL ([TR-2](PROJECT_CONTEXT.md#technology-requirements-and-restrictions)).
- Every group member submits individually ([OC-5](PROJECT_CONTEXT.md#shared-operational-constraints)).

**Dependencies**

- Stated: P1.5 depends on P1.3 and P1.4 ("After these additions/changes").
- Suggestion (inferred): P1.1 informs the actors used in P1.2.

**Ambiguities:** [DA-1](#ambiguity-register) (deadline year), [CA-1](PROJECT_CONTEXT.md#context-ambiguities) (address relationship, affects P1.3.3 and P1.4.5), [CA-4](PROJECT_CONTEXT.md#context-ambiguities) (demographic field placement, affects P1.4.2), [CA-5](PROJECT_CONTEXT.md#context-ambiguities) (general employee search scope, affects P1.2).
